# Workflow: Compile the Report

For requests to compile the LaTeX report, build/generate the report PDF, or check that
`report/main.tex` still compiles cleanly.

## Command

Run from `report/`:

```
latexmk -pdf -interaction=nonstopmode -outdir=. -auxdir=build_artifacts main.tex
```

This matches the VSCode LaTeX Workshop settings in `capstone.code-workspace`
(`outDir=%DIR%`, `auxDir=%DIR%/build_artifacts`) — the PDF lands in `report/main.pdf`,
everything else in `report/build_artifacts/`. latexmk auto-detects the biblatex+biber
backend from `main.bcf` and runs biber automatically; no separate `biber` invocation is
needed.

## Verifying success

1. Check the command's exit code and the tail of its output for
   `Latexmk: All targets (...) are up-to-date` / `Output written on ... main.pdf` with no
   `Latexmk: Errors`.
2. Confirm `report/main.pdf` exists and its timestamp is newer than the `.tex` files just
   compiled.
3. Skim `report/build_artifacts/main.log` for a line starting `! ` (LaTeX's fatal-error
   marker) even if a PDF was produced — nonstopmode can still emit a PDF through a real
   error partway down the file.
4. Report page count and any `LaTeX Warning: Citation '...' undefined` /
   `Reference '...' undefined` / missing-figure warnings to the user even on an otherwise
   clean build — these usually mean content hasn't been written yet (a `\cite{}` key not
   in `references/references.bib`, a `\ref{}` to a label that doesn't exist yet, a
   `\includegraphics{}` file not yet added to `report/figures/`), not a build bug to
   silently absorb.

## Self-resolvable errors — fix and recompile without asking

- **Undefined control sequence** from a missing package: add the right `\usepackage{}` to
  `main.tex`'s preamble.
- **Unescaped special character** (`%`, `$`, `&`, `#`, `_`, `^`, `~`) typed literally in
  text mode → escape it (`\%`, `\&`, `\#`, `\_`, etc.) or wrap in `$...$` if it was
  actually meant as math.
- **Wrong or missing file extension** on `\includegraphics{}` when the intended file is
  unambiguous (e.g. exactly one file in `report/figures/` with that basename).
- **Typo'd `\ref{}` / `\label{}` / `\cite{}` key** that's a near-exact match to an
  existing label or bib key elsewhere in the report (dropped character, wrong case) → fix
  the typo.
- **Duplicate `\label{}`** → rename the newer one to something distinct and descriptive.
- Recompile after each fix; if the log shows several independent errors in one pass, fix
  them all before reporting back rather than stopping at the first.

## Flag to the user instead of guessing

- A `\cite{}` key or `\ref{}`/`\label{}` target that doesn't exist anywhere and isn't a
  typo of something that does — say what's missing and where, don't fabricate content.
- A referenced figure file that's genuinely absent from `report/figures/` (or the other
  `\graphicspath` locations in `main.tex`) — don't invent a placeholder image.
- Any fix that would require renaming a `references.bib` key already used elsewhere, or
  restructuring section content — bibliography keys and section content are the user's
  call, not the build's.
- Package-installation failures (MiKTeX/TeX Live can't find or install a package) —
  report the missing package name.
- Anywhere two plausible fixes exist and the right one depends on intent (e.g. an
  unbalanced brace where it's unclear which side has the typo).

## Notes

- Don't hand-edit anything in `report/build_artifacts/` — it's fully regenerated by
  latexmk on every run and is gitignored.
- If `report/main.tex` doesn't exist at all, this isn't a compile-debugging situation —
  the report scaffold itself needs to be (re)built. Say so rather than inventing a new
  structure; the section layout and `Project_To-Do List.md` mapping are documented in
  `report/README.md` and the mapping comment at the top of `main.tex`.
